## Что изменено в исходниках

- Settings → Appearance → Pearl Flow: выбор Pearl Mist, Arctic Pearl и Midnight Pearl.
- Редактор пресета: четыре цвета фона, системный выбор цвета, прозрачность панелей и переход к штатному выбору изображений. Предпросмотр использует настоящий ThemePreviewController.
- Применение локального Pearl-пресета идёт через штатный селектор Appearance без ожидания загрузки темы в облако. Сохранение и автоматическая ночная тема используют настройки Telegram. Поведение после входа ещё требует проверки.
- Настроены цвета списка чатов, настроек, навигации, исходящих сообщений и четырёхцветные градиенты фона. Использованы штатные стеклянные элементы Telegram.
- У голосовой волны появился мягкий голубой перелив по позиции настоящего проигрывателя. Пауза останавливает движение, перемотка меняет его позицию. При Reduce Motion декоративная фаза неподвижна. Одноразовые сообщения и эффект транскрибирования исключены.
- Перелив включается только для трёх тем с указанными названиями. Для переименованных пользовательских тем отдельный переключатель пока не реализован.

- Для Pearl-тем: мягкие градиенты карточек чатов и действий профиля.
- Музыка профиля: стеклянная карточка с жемчужным отражением и увеличенной областью нажатия, открывающая штатный экран сохранённой музыки. Карточка появляется только при наличии настоящего трека в данных Telegram. Анимация эквалайзера и фиктивное воспроизведение не добавлены.
- Украшения профиля: настоящие подарки аккаунта, локальные перемещение и масштабирование до 12 элементов; удержание, перетаскивание, щипок, Отмена / Сбросить / Готово и действия VoiceOver. Расстановка видна только на этом устройстве и не публикуется на сервер.
- Pearl-анимации: медленное покачивание без звёздных частиц и пульсирующего свечения. Декоративное движение останавливается во время редактирования, вне иерархии, при уходе приложения в фон и при Reduce Motion.
- Для музыки предусмотрена непрозрачная подложка при Reduce Transparency.

Это UIKit / AsyncDisplayKit внутри Telegram-iOS. Отдельного веб-клиента, фиктивных переписок, имитации входа или замены серверного слоя здесь нет. Используется существующий клиентский стек Telegram-iOS; дополнительный TDLib-слой не добавлен.

## Сборка без собственного Mac

GitHub Actions выполняет проверки на `macos-26` с Xcode 26.6, указанным в `versions.json`.

Workflow **Pearl Flow Swift syntax** проверяет синтаксис восьми изменённых Swift-файлов. Проверка синтаксиса не является проверкой типов или поведения.
Workflow **Pearl Flow native verification** получает исходники зависимостей из upstream, собирает полный `Telegram/Telegram` для ARM64-симулятора, сохраняет архив приложения, затем пробует установить и запустить его на чистом iOS-симуляторе.

После успешных соответствующих шагов в Artifacts появляются:

- `pearl-simulator-compile-only`: архив приложения **для симулятора**, не для установки на iPhone.
- `pearl-simulator-startup`: журнал запуска, сведения о runtime и снимок экрана через 15 секунд.
- `pearl-build-log`: журнал компиляции, в том числе при ошибке сборки.

Артефакты хранятся 3 дня. Отсутствие приложения при неуспешной сборке не скрывается. Снимок запуска не является проверкой дизайна или демонстрацией функций. Сборки выполняются последовательно; новый commit заменяет ожидающую сборку, но не прерывает уже работающую.

**CI использует TELEGRAM_API_ID и TELEGRAM_API_HASH из repository secrets, когда присутствуют оба корректных значения.** Без них собирается конфигурация без рабочего входа. При наличии настоящих данных публичный незашифрованный архив отключён; архив для Appetize шифруется публичным сертификатом получателя. Закрытый ключ не находится в репозитории. Не загружайте в публичные артефакты приложение с учётными данными или контейнер вошедшего аккаунта. Успешный запуск не подтверждает вход и работу переписок. Каждая сборка получает номер GITHUB_RUN_NUMBER.

## Локальная разработка на Mac

1. Получить эту ветку и зависимости. Для fork нужны upstream-адреса относительных submodule:

```sh
git clone --branch pearl-flow-macos-check https://github.com/pupupupupu/Telegram-iOS.git
cd Telegram-iOS
git submodule init
git config submodule.submodules/rlottie/rlottie.url https://github.com/TelegramMessenger/rlottie.git
git config submodule.submodules/TgVoipWebrtc/tgcalls.url https://github.com/TelegramMessenger/tgcalls.git
git submodule update --init --recursive
```

2. Использовать Xcode из `versions.json` и собственные данные приложения Telegram по инструкции корневого README. Секреты, Apple-сертификаты и конфигурацию аккаунта не коммитить. Не использовать подпись и закрытые репозитории сопровождающих upstream.
3. Полная воспроизводимая команда проверки и отключение device provisioning **только для симулятора** находятся в `.github/workflows/pearl-native-check.yml`. Для реального аккаунта нужна собственная конфигурация; для установки на iPhone дополнительно нужна корректная Apple-подпись.
